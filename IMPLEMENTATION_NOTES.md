# Implementation Notes — Tracked Open Items
These are **not resolved**. Each is a placeholder or a deliberately conservative default, not a product decision. Do not treat any of the code referenced below as final — resolve the underlying product question first (see PRODUCT_DECISIONS.md / SCREEN_BLUEPRINTS.md / USER_JOURNEYS.md Readiness Checks), then update the referenced code.

Items 10–12 were added by the 24 August 2026 client-revision pass — see [REVISION_LOG.md](./REVISION_LOG.md) for what that pass changed, which approved decisions it amends, and what still needs client sign-off.

| # | Item | Where it lives in code | Current placeholder behavior |
|---|---|---|---|
| 1 | Status color extension for rejected states | `src/app/globals.css` (`--color-status-rejected`) | A non-brand muted terracotta, chosen for legibility, pending sign-off from whoever owns the Brand Guidelines |
| 2 | Admin journey-level design | `src/app/admin/**` (overview with clickable stat tiles, users, listings with Properties/Services/Ads tabs + search/filter, complaints, activity/audit-log pages), `src/lib/auth-context.tsx` (`isAdmin`), `src/lib/admin-client.tsx` (`useAdminUsers`/`useAdminListings`/`useAdminComplaints`/`useAdminAuditLog`/`fetchUserDocument`/`fetchAdReview`), `src/components/admin/DocumentReviewDialog.tsx`, `src/components/admin/AdReviewDialog.tsx`, `login/page.tsx` | Admin identification is real and backend-verified: `isAdmin` is a persisted `Boolean` column on `User` (`schema.prisma`), returned by `GET /auth/me` and read as `user?.isAdmin` in `login/page.tsx` — no hardcoded email list, no `admin.ts`, no `loginAsAdmin()`; that placeholder layer was removed entirely. No self-serve path sets the flag — an admin account is provisioned directly (Prisma Studio/script). Users/Listings/Complaints/Ads all moderate real data via `nexthome-api`'s `admin.routes.js`, with confirmation dialogs before every action. Ads share the same `/admin/listings` endpoint via a third `kind: "advertisement"` rather than a separate route. The audit log (Activity tab) is now a real, persisted table (`AuditLogEntry`), not client-side state — it survives reloads and attributes each entry to the acting admin. AWS S3 is now configured on the live Railway deployment (bucket private, `Block Public Access` on). Admins can now view what was actually uploaded before acting: a pending user role's document is shown through a 5-minute signed `GetObject` URL (private by design — the raw S3 key never reaches the client; see `lib/s3.js`'s `getSignedReadUrl`/`objectExists`), and a pending ad's image is shown unsigned (public by design, via a bucket policy scoped to the `ads/`/`listings/` prefixes). Only the document dialog blocks Verify on actually having seen the file — a broken/placeholder ad image doesn't block Approve/Reject, since the ad's text and link are still reviewable on their own |
| 3 | Complaints form access model | `src/app/(public)/complaints/page.tsx` | Left open/unauthenticated as a conservative default; explicitly commented in the file as unresolved |
| 4 | Exact messaging verification gate | `src/components/property/ListingActions.tsx`, `ServiceContactAction.tsx`, `src/app/dashboard/messages/page.tsx` | Messaging is currently gated on authentication only (`useAuthGate`), not on role-verified state — intentional, since gating it further would be inventing the resolution |
| 5 | Review timeframe + rejected-item resubmission mechanism | `src/components/ui/StatusBanner.tsx` (pending copy), listing/service/ad detail pages | No duration stated; rejected items show status but no defined resubmit flow beyond a generic "Edit" |
| 6 | Effect of a lapsed subscription on a live listing | Not modeled | `subscriptionState` only gates *new* publication in `src/app/dashboard/listings/new/page.tsx`; nothing revokes a listing that's already live |

| 8 | Whether editing a live listing re-triggers review | `src/app/dashboard/listings/[id]/page.tsx`, `nexthome-api/src/routes/listings.routes.js` | "Edit Listing" now saves title, description, price and bedrooms (`PATCH /listings/:id`), and an edit to a live listing goes live immediately with no re-review. Whether it *should* re-trigger review is still an open product question |
| 9 | Final login credential mechanism | `src/app/login/page.tsx`, `nexthome-api/src/routes/auth.routes.js` | Login is real: email + password against the backend, a short-lived JWT access token (in memory) and a rotating refresh token in an httpOnly cookie, revocable server-side on logout. What is still open is the *final* credential design (e.g. phone or social login) |
| 10 | Detail-page gating | `src/components/property/ListingDetailGate.tsx`, `nexthome-api/src/routes/listings.routes.js` | Enforced server-side: `GET /listings/:id` returns anonymous callers a redacted record (`redactForAnonymous`), so gated fields never reach the page. The exact teaser scope (what an anonymous visitor may see) is still awaiting client sign-off |
| 11 | Session/auth state across page reloads | `src/lib/auth-context.tsx`, `src/lib/token-storage.ts` | Sessions now survive a reload: the access token lives in memory and is re-issued from the httpOnly refresh cookie via `POST /auth/refresh`. Only the *active role preference* is kept in `localStorage["activeRole:" + user.id]`, per account and surviving logout by design (PRODUCT_DECISIONS.md "Role Selection & Active-Role Model" §2) |
| 12 | Error/rejected colour vs. the "no invented shades" rule | `src/app/globals.css` (`--color-status-rejected`) | Website Revision Spec §3D requires every colour to match a brand hex exactly. The Brand Guidelines define no error colour, and reusing a brand blue would make "rejected" and "verified" indistinguishable. Escalates #1 rather than replacing it — still needs a brand-owner decision. |

None of these were silently resolved — not during the original audit pass, and not during the client-revision pass that followed. Where a fix touched adjacent code (e.g. gating listing/service *submission* on role-verified state, which the docs *do* already specify), that was implemented; every item above was left exactly as open as it was found.
